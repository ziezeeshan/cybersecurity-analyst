# Plumsail Vulnerability Report

## Summary
A **Stored Cross-Site Scripting (Stored XSS)** vulnerability was discovered in the Plumsail Forms platform.  
The issue occurs when malicious payloads are injected into a form, which then executes arbitrary JavaScript in the victim’s browser when the form is viewed.

---

## Affected Endpoint
- **Form Designer URL:**  
  https://account.plumsail.com/forms/designer/2e3ec09c-7185-4e8c-aa94-75b28b00e46d  

- **Form Preview (Payload Execution):**  
  https://zeepubity.plumsail.io/preview/render/2e3ec09c-7185-4e8c-aa94-75b28b00e46d  

---

## Vulnerability Details
The injected payload executes successfully, and we confirmed this using an **xss.report** account.  
Upon execution, the payload exfiltrated sensitive client-side information to our controlled endpoint.

### Data Captured on `xss.report` Dashboard
- **Referrer:** https://account.plumsail.com/  
- **Origin:** https://zeepubity.plumsail.io  
- **URI:** https://zeepubity.plumsail.io/preview/render/2e3ec09c-7185-4e8c-aa94-75b28b00e46d  
- **User-Agent:** Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/137.0.0.0 Safari/537.36  
- **Language:** en-US  
- **IP Address:** 66.102.122.72  
- **Port:** 45968  
- **GPU Info:** ANGLE (Intel, Mesa Intel(R) HD Graphics 2500 (IVB GT1), OpenGL 4.2)  
- **Local Storage Dump:** Included DOMInvader settings, submission IDs, and cached session-related data.  
- **DOM Snapshot:** Extracted DOM content of the rendered form, showing potential access to sensitive data.

---

## Impact
- **Session Hijacking:** Potential theft of authentication tokens if cookies were accessible.
- **Sensitive Data Exposure:** Local storage entries and form submission IDs were exfiltrated.
- **Privilege Escalation:** Attackers could impersonate users or escalate privileges via stolen tokens.
- **Business Logic Abuse:** Since Plumsail handles document workflows and forms, attackers could compromise sensitive business data.

This vulnerability falls under **“Stored Cross-Site Scripting (Stored XSS)”**, which is explicitly listed as **in-scope** and **reward eligible** in Plumsail’s bug bounty program.

---

## Steps to Reproduce
1. Log in to [Plumsail Forms Designer](https://account.plumsail.com/forms/designer/2e3ec09c-7185-4e8c-aa94-75b28b00e46d).  
2. Insert one of the provided payloads into a form field.  
3. Save the form and open the **Preview URL**:  
   https://zeepubity.plumsail.io/preview/render/2e3ec09c-7185-4e8c-aa94-75b28b00e46d  
4. The payload executes and exfiltrates information to the attacker-controlled **xss.report** account.

## Proof of Concept (PoC)
- Created account on **xss.report** to log captured data.  
- Payloads triggered successfully on form preview.  
- Verified data captured:  
  - Browser fingerprinting info  
  - IP address and network details  
  - Local storage entries  
  - DOM snapshot  

---

## Recommendation
- Implement **proper input sanitization and output encoding** for all form inputs.  
- Enforce a strict **Content Security Policy (CSP)** to block external script execution.  
- Validate and sanitize HTML before rendering form content.  
- Consider using libraries like **DOMPurify** to prevent XSS payload execution.

---

## Severity
**High** — Stored XSS allowing persistent malicious script injection, leading to **sensitive data exposure** and **potential account takeover**.
